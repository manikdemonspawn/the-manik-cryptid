# Webflow Collaboration — resource notes (2026-10-11)

Source: https://webflow.com/feature/collaboration

## Core idea
Roles and permissions per person: designers, developers, marketers, content editors, reviewers, admins each get the right tools and access.

## Key features
- **Real-time co-editing** on the canvas with visible name badges.
- **Roles**: designer / developer / marketer / editor / reviewer / admin — invite instantly.
- **Branching**: test changes in isolated branches, stage for QA, submit for approval.
- **Review flow**: in-context commenting + shareable review links; reviewers can approve changes.
- **Content editing**: editors update text/images/metadata right on the page or in the CMS — no design access needed.
- **Analytics + A/B testing + personalization** built in (ties to Optimize guide filed).
- **AI assistant**: generate sites/sections, on-brand copy, SEO/AEO optimization.

## Agency/client features
- Guest role for joining a client's Workspace safely.
- Centralized feedback in Webflow (no third-party tool needed).
- Client invoicing/payment handling inside Webflow.

## Enterprise controls
- Custom roles, site activity log (what/when/who), per-site/per-page/per-collection/per-locale access restriction, staging vs production publish control.

## Why it matters for the-manik-cryptid build
- Right now it's a one-woman shop, but the reviewer role + shareable review links = Manik can send Gremmy/Adam preview links for feedback without giving edit access.
- Editor role = later, if someone else posts to the blog, they can't break the design.
- Branching = safe experimentation without touching the live site.
